# Проверка безопасности и качества «Понятного» (версия 2.1)

Дата: 21 октября 2026. Проверялись: лексер, парсер, семантическая проверка, генератор JavaScript, среда выполнения (`makeRuntime`), CLI (`запустить`, `собрать`, `компилировать`, `проверить`, `перевести`), сборка `.exe` (Node.js SEA + дописанная программа), песочница `public/index.html`, переводчик в Python/JavaScript/C# и обратно.

Метод: ручной разбор кода; попытки атак (внедрение кода через строки и имена, выход к `Function`, prototype pollution, Trojan Source, омоглифы, переполнение стека, огромные строки, перезапись файлов); сравнение с тем, как это решают rustc, GCC, Python и браузеры; фаззинг (6000 случайных программ и строк, `test/bezopasnost.test.js`).

## Итог по степени серьёзности

| # | Серьёзность | Проблема | Статус |
|---|---|---|---|
| 1 | Высокая | Песочница выполняла программу прямо на странице (`new Function` в контексте сайта). Программа могла дотянуться до внутренних свойств JavaScript (`x.constructor`, `x.__proto__`, `x.__lookupGetter__`, методы `Object.prototype` через таблицы функций строк/списков). Полного выхода к `Function` я не нашёл, но защиты по сути не было: одна ошибка в среде выполнения — и код получает доступ к странице (localStorage, DOM). | Исправлено: код выполняется в `iframe sandbox="allow-scripts allow-modals"` (отдельный «пустой» источник, нет доступа к странице и её хранилищу), на странице задана CSP; в языке закрыт доступ к внутренним именам (белый список: только собственные поля и функции классов программы). |
| 2 | Высокая | Подмена программы на Windows (CWE-427): компилятор и **каждая собранная программа** вызывали `execSync("chcp 65001")` через `cmd.exe`, а `cmd.exe` ищет `chcp` сначала в текущей папке. Файл `chcp.bat` рядом с программой (например, в «Загрузках») выполнился бы при запуске. | Исправлено: `execFileSync(%SystemRoot%\System32\chcp.com)` без оболочки. Программы, собранные версией 2.0, остаются уязвимыми — их нужно пересобрать. |
| 3 | Средняя | Prototype pollution: `объект.__proto__ = …` меняло прототип объекта; поля `__init`, `__cls` можно было перезаписать и сломать классы. | Исправлено: имена `__…`, `constructor`, `prototype` и др. запрещены после точки и для полей/функций классов; запись полей идёт через `defineProperty`; таблицы встроенных функций проверяются через `hasOwnProperty`. |
| 4 | Средняя | Trojan Source (CVE-2021-42574): символы направления текста U+202A–202E, U+2066–2069 принимались в строках и комментариях. | Исправлено: запрещены во всём тексте (как lint `text_direction_codepoint_in_literal`/`…_in_comment` в rustc 1.56.1), вместе с U+200E/200F/061C и невидимыми U+200B–200D, U+2060, U+00AD; для строк есть `\u{…}`. |
| 5 | Средняя | Омоглифы: `сoк` (латинская o) и `сок` — два разных имени, которые выглядят одинаково. | Исправлено: смешение кириллицы и латиницы в одной части имени запрещено (по идее UTS #39, «mixed-script confusables», как lint `mixed_script_confusables` в rustc), с подсказкой правильного написания; текст приводится к NFC; совместимые формы (`ﬁ`) в именах запрещены. |
| 6 | Средняя | Перезапись файлов при сборке: `собрать prog` (без `.pon`) на Linux записывал программу **поверх исходника**; `-o` мог указать на сам компилятор или исходник. | Исправлено: выходной файл проверяется (путь и inode) — не исходник, не основа сборки, не сам компилятор, не папка; без `.pon` выход получает `.bin`. Так же для `компилировать` и `перевести`. |
| 7 | Средняя | Отказ в обслуживании: `((((…1…))))` или 5000 минусов подряд роняли компилятор с необработанным `RangeError` и стеком Node.js; `"a" * 10^12` и удвоение строки в цикле выдавали неверное «слишком глубокая рекурсия». | Исправлено: глубина вложенности ≤ 200 (понятная ошибка), строки ≤ 10^8 символов, ошибки `RangeError` различаются (стек / длина строки / длина списка); подсказки опечаток не считаются для слов длиннее 40 символов. |
| 8 | Низкая | `подключи "путь"` читал любой существующий файл (например, `../../etc/passwd`) и выдавал кусок его содержимого в сообщении об ошибке. | Исправлено: подключаются только файлы `.pon`. Подключение `.pon` из других папок (`../общий.pon`) разрешено намеренно. |
| 9 | Низкая | Неоднозначность грамматики: `a < b < c` и `a == b == c` молча считались как `(a < b) < c`. | Исправлено: цепочка сравнений — ошибка с подсказкой «a < b и b < c». |
| 10 | Низкая | Переводчик: в C# имена не экранировались (`пусть class = 1` давало неверный C#); имена пользователя могли совпасть со вспомогательными функциями перевода (`показать`, `длина`); перевод из Python не понимал Юникод-имена и не учитывал NFKC (`ﬁle` и `file` в Python — одно имя); `$x` из JavaScript давал неверный код «Понятного». | Исправлено: общий переименователь без коллизий (`makeRenamer`), ключевые слова C#, имена подготовительного кода, NFKC для Python, безопасное преобразование имён в «Понятный». |
| 11 | Низкая | В репозитории не было `LICENSE`, `licenses/`, `THIRD_PARTY_NOTICES.md`, поэтому `npm test` и `npm run build:exe` падали на чистой копии. | Исправлено (тексты восстановлены из `src/licenzii.js`, лицензии acorn и Node.js — из оригиналов). |
| 12 | Низкая | Неточные сообщения: «ожидалось конец строки», «Может быть, …?» без всех вариантов; при опечатке в служебном слове — только остановка. | Исправлено: «ожидался конец строки … Каждая команда пишется на отдельной строке», «Возможно, вы имели в виду «а» или «б»?», подсказки для `'` и `;`, коды символов U+XXXX; безопасная автозамена опечаток (раздел 14а синтаксиса). |
| 13 | Информация | `ponyatny.exe` и собранные `.exe` не подписаны (после вставки программы подпись Node.js становится недействительной — `postject` пишет «signature seems corrupted»). Программа дописывается в конец файла без подписи, поэтому её может изменить любой, кто может изменить сам файл. | **Не исправлено**: нужен сертификат Authenticode (`signtool sign /fd SHA256`). | 15 | Информация | В песочнице бесконечная работа внутри одной встроенной функции (не цикла программы) может подвесить вкладку: `iframe` может работать в том же потоке, а 20-секундный таймер не прерывает синхронный код. Циклы и рекурсия ограничены. | Частично. Полное решение — Web Worker, но тогда не работает синхронный `спроси`. |

## Что проверено и оказалось в порядке

- Внедрение кода через строки: все строки идут через `JSON.stringify`, вставки `{…}` разбираются как выражения «Понятного», а не как текст JS. `"); throw 1; ("`, `${…}`, `</script>`, U+2028 выводятся как текст (тест «строки не могут внедрить JavaScript»).
- Внедрение через имена: имена состоят только из букв, цифр и `_` и получают префикс `$`, поэтому не совпадают со служебными словами JS и внутренними `__R`, `__o1`.
- Числа выводятся через `String(число)` после разбора лексером (только цифры).
- `eval` не используется; `new Function` — только для уже сгенерированного компилятором кода.
- Словари — это `Map`, поэтому ключи `__proto__`/`constructor` в словаре безопасны.

## Сравнение со зрелыми компиляторами и источники

- Rust: [Security advisory for rustc (CVE-2021-42574)](https://blog.rust-lang.org/2021/11/01/cve-2021-42574/) — запрет символов направления в строках и комментариях с подсказкой `\u{…}`; сделано так же.
- Статья авторов атаки: N. Boucher, R. Anderson, [Trojan Source: Invisible Vulnerabilities](https://trojansource.codes/) (CVE-2021-42574, CVE-2021-42694 — омоглифы).
- Unicode [UTS #39 Security Mechanisms](https://www.unicode.org/reports/tr39/) (смешение алфавитов, confusables) и [UTS #31 Identifiers](https://www.unicode.org/reports/tr31/) (нормализация имён).
- Python: [PEP 3131](https://peps.python.org/pep-3131/) (имена не-ASCII, NFKC) и [PEP 672](https://peps.python.org/pep-0672/) (Unicode-проблемы безопасности в Python).
- GCC 12: предупреждение [`-Wbidi-chars`](https://gcc.gnu.org/onlinedocs/gcc/Warning-Options.html#index-Wbidi-chars).
- Песочница: MDN [`<iframe sandbox>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/iframe#sandbox) и [Content Security Policy](https://developer.mozilla.org/en-US/docs/Web/HTTP/CSP).
- OWASP [Prototype Pollution Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Prototype_Pollution_Prevention_Cheat_Sheet.html).
- [CWE-427: Uncontrolled Search Path Element](https://cwe.mitre.org/data/definitions/427.html) и порядок поиска команд в `cmd.exe` (текущая папка первой).
- Node.js [Single executable applications](https://nodejs.org/api/single-executable-applications.html) — после вставки блоба исполняемый файл нужно подписать заново.
